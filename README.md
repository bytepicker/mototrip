# MotoTrip — планировщик мотопутешествий

SPA для планирования поездок на мотоцикле. React + TypeScript + Vite + Leaflet.

## История версий

### Версия 0.2.1 (исправление поиска объектов)

- Поиск POI использует компактный запрос: до 12 точек вдоль трека с радиусом 3,5 км.
- Добавлены резервные Overpass endpoints: VK Maps, Private.coffee и FOSSGIS.
- Добавлены таймаут запроса и проверка поля `remark`: Overpass может сообщить о runtime timeout даже при HTTP 200.
- Расширена классификация достопримечательностей по тегам `historic` и `natural`.

### Версия 0.2.0

- Маршрут строится через **все точки списка** в указанном порядке: старт, достопримечательности, заправки, кемпинги, магазины, кафе, сервисы, промежуточные точки и финиш.
- После успешного построения маршрута приложение автоматически ищет объекты OpenStreetMap вдоль линии маршрута через Overpass API.
- Найденные POI отображаются отдельными маркерами. Категории можно включать и выключать.
- В карточке найденного объекта можно добавить его в маршрут. Добавленная точка становится полноценной маршрутной остановкой.
- После изменения координат или порядка точек линия помечается как устаревшая; маршрут можно перестроить.
- Экспорт GPX: все плановые остановки экспортируются как GPX waypoints, построенная дорожная геометрия — как track.
- Импорт GPX: читаются waypoints/route points; существующая геометрия track сохраняется на карте. Если в файле нет waypoints/route points, используются начало и конец track.
- Сохранены функции прототипа: несколько маршрутов, локальное сохранение, ссылки, JSON import/export, поиск места.

## Запуск

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Сборка: `npm run build`.

## GitHub Pages

Workflow находится в `.github/workflows/deploy.yml`. Загрузи содержимое проекта в `main`, выбери **Settings → Pages → Build and deployment → GitHub Actions**. При push workflow соберёт `dist` и опубликует сайт.

## Источники данных и ограничения

- Карта и POI: OpenStreetMap, лицензия ODbL. Сохраняй атрибуцию.
- POI: NextGIS Overpass API. Запрос выполняется после построения маршрута; есть клиентская пауза между запросами. Публичные экземпляры — общие ресурсы, могут быть перегружены или временно недоступны. Не запускай массовый поиск и не используй публичный Overpass как гарантированный backend для большого публичного сервиса.
- Геокодирование: публичный Nominatim, запрос только по кнопке.
- Маршрутизация: публичный OSRM demo endpoint, автомобильный профиль, best-effort без SLA. В запрос передаются все точки списка, поэтому маршрут проходит через добавленные места. Для регулярной/массовой нагрузки понадобится отдельный routing backend.
- Данные поездок хранятся в LocalStorage браузера. Ссылки содержат сериализованный маршрут в URL hash.

### Версия 0.3.0 — NextGIS Overpass для POI

Поиск объектов на карте переведён на NextGIS Overpass API. Для работы необходимо создать персональный ключ в личном кабинете NextGIS (раздел «Программы и сервисы» → «Overpass API» → «Создать API-ключ»), затем открыть панель «Объекты на карте» → «Источник: NextGIS Overpass», вставить ключ и сохранить.

Ключ сохраняется в LocalStorage текущего браузера и не включается в исходники или сборку. Однако запросы выполняются непосредственно из браузера, поэтому ключ виден пользователю в DevTools/сетевых запросах. Для публичного многопользовательского сервиса в будущем потребуется backend/proxy с ограничением доступа и кешированием.

Документация: https://docs.nextgis.ru/docs_ngcom/source/services.html


## Версия 0.4.0 — кэш POI и автоматический порядок остановок

- Результаты поиска NextGIS Overpass кэшируются в LocalStorage на 7 дней. Кэш ограничен 40 последними коридорами маршрутов; ошибки квоты LocalStorage не мешают поиску.
- При повторном построении того же маршрута POI загружаются из кэша без обращения к NextGIS. Кнопка «Обновить объекты вдоль маршрута» принудительно запрашивает свежие данные.
- Новая остановка добавляется перед отмеченным финишем, а не после него.
- Кнопка «Автоматически упорядочить остановки» получает матрицу дорожных расстояний OSRM, фиксирует старт и финиш, подбирает порядок промежуточных остановок алгоритмом ближайшего соседа с улучшением 2-opt и сразу перестраивает маршрут. Это практическая эвристика, не гарантия математически глобального минимума.
- Если старт/финиш не назначены явно, используются первая и последняя точки списка. Чтобы явно закрепить их, выбери точку в списке и измени её категорию в редакторе.
